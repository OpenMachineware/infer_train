# K-quant MV算法优化分析

## 当前状态

所有K-quant MV内核已与llama.cpp对齐，性能相当（~100%）。

## 优化方向分析

### 1. simdgroup_matrix (潜力大但复杂)
- **优势**: Apple官方称37%矩阵乘法提升
- **问题**: 仅适用于FP32/FP16，需要解量化
- **适用性**: 量化格式优势在于内存带宽，解量化会抵消

### 2. 数据布局重排
- **当前**: hmask[32], qs[64], scales[12], d
- **问题**: scales和d在block末尾，cache miss
- **方案**: 将scales和d移到block开头
- **影响**: 改变数据格式，不兼容llama.cpp

### 3. 线程分配优化
- **当前**: tiisg/4分配，32线程/线程组
- **问题**: 可能未充分利用SIMD宽度
- **方案**: 调整tiisg分配策略
- **风险**: 需要验证所有边界情况

### 4. 循环展开策略 (已验证)
- **发现**: Q3_K用普通for比FOR_UNROLL快~4%
- **原因**: 复杂循环体增加寄存器压力
- **已应用**: Q3_K已修改

## 实际可行的优化

### 短期 (不改数据格式)
1. ✅ 循环展开策略 - 已优化Q3_K
2. 🔄 内存预取 - 可尝试prefetch指令
3. 🔄 寄存器分配 - 可尝试减少局部变量

### 中期 (需验证)
1. 改变线程索引分配
2. 合并多个block的计算
3. 使用Metal SIMD函数优化位操作

### 长期 (改变数据格式)
1. 重新设计BlockQ3K结构
2. 使用自定义量化方案
3. 支持混合精度

## 结论

**在不改变数据格式的前提下，算法优化空间有限（~5%）。**
**要显著超越llama.cpp，需要重新设计量化格式或使用Apple特有的硬件功能。**
