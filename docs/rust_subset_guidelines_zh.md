# Rust 安全子集开发规范

## 1. 核心心智：用“所有权”代替“手动内存管理”

- **尽量只用 `String` 和 `Vec`**：它们是 Rust 里最核心的 RAII 容器，自动分配和释放内存。
- **多用 `&T`（不可变借用）**：日常传参和读取数据，尽量只传引用，避免不必要的深拷贝（`.clone()`）。
- **少用 `&mut T`（可变借用）**：只在真正需要修改数据时才用，保持数据的不可变性（Immutability）是写出安全代码的捷径。
- **不碰 `unsafe`**：绝对不要使用 `unsafe` 块和裸指针，把内存安全的脏活累活全交给编译器。

## 2. 类型与接口：保持简单

- **只用 `struct` 和 `enum`**：用来组织数据，不要搞复杂的泛型约束（Trait Bounds）。
- **只用基础的 Trait**：比如 `Debug`、`Clone`、`Copy`，不要去自己设计复杂的 Trait 继承体系，除算子实现之外别去搞泛型编程（Monomorphization）。
- **不用复杂的宏**：只用 `#[derive(...)]` 这种声明宏来自动生成代码，绝不碰 `macro_rules!` 或过程宏（Procedural Macros）。

## 3. 控制流与错误处理：直白易懂

- **只用 `match` 和 `if let`**：用来处理 `Option` 和 `Result`，直观且安全。
- **只用 `?` 操作符**：这是 Rust 里最优雅的异常处理方式，遇到错误直接向上抛出，不写复杂的错误转换逻辑。
- **不碰高级函数式**：只用最基础的 `.map()`、`.filter()`、`.iter()`。遇到稍微复杂的逻辑，直接老老实实写 `for` 循环，绝不写嵌套的迭代器链或闭包。

## 4. 并发模型：求稳为主

- **只用 `std::thread`**：最朴素的操作系统级线程，配合 `Arc<Mutex<T>>` 进行数据共享。
- **不碰 `async/await` 生态**：Rust 的异步模型极其复杂，如果没有高并发性能瓶颈，坚决不用 `tokio` 或 `async`，同步代码永远是最容易调试的。
